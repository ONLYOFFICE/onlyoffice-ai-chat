# Internationalization (i18n)

`@onlyoffice/ai-chat` ships with 41 bundled locales and uses **i18next** under the hood. Locale bundles are lazily loaded -- only the active locale and the English fallback are fetched at runtime.

## Setting the Locale

Pass the `locale` prop to `AIChatWidget`:

```tsx
<AIChatWidget locale="fr" storage={storage} settings={settings} platform={platform} storeKeys={keys} />
```

When the prop changes, the new locale bundle is loaded lazily and the UI re-renders.

## RTL Support

Arabic (`ar-SA`) is automatically detected as an RTL language. When active, the widget sets `dir="rtl"` on its root element and applies RTL-aware layout classes throughout. Hebrew (`he`) and Urdu (`ur`) are RTL scripts -- to enable full RTL layout for these locales, add them to your own wrapper or contribute them upstream.

The `useI18n` hook exposes RTL state:

```ts
const { isRTL, direction } = useI18n();
// isRTL: boolean
// direction: "ltr" | "rtl"
```

## Custom Translations (Partial Overrides)

Override individual translation keys for the current locale via the `translations` prop:

```tsx
<AIChatWidget
  locale="en"
  translations={{ AIAgent: "AI Assistant", Send: "Submit" }}
  // ...other props
/>
```

Overrides are merged on top of the bundled locale using `i18n.addResourceBundle(..., true, true)`, so you only need to provide the keys you want to change.

## Custom Languages

Register entirely new languages that are not bundled via the `customLanguages` prop on `I18nProvider`:

```tsx
<I18nProvider
  locale="my-lang"
  customLanguages={{
    "my-lang": {
      AIAgent: "Custom Agent",
      Send: "Go",
      // ...partial or full translation map
    },
  }}
>
  <App />
</I18nProvider>
```

## Headless Usage with I18nProvider / useI18n

When building a custom layout outside of `AIChatWidget`, wrap your tree with `I18nProvider` directly:

```tsx
import { I18nProvider, useI18n } from "@onlyoffice/ai-chat";

function App() {
  return (
    <I18nProvider locale="de">
      <MyCustomUI />
    </I18nProvider>
  );
}

function MyCustomUI() {
  const { t, locale, changeLocale, isRTL, direction } = useI18n();

  return (
    <div dir={direction}>
      <h1>{t("AIAgent")}</h1>
      <button onClick={() => changeLocale("fr")}>Switch to French</button>
    </div>
  );
}
```

### I18nProviderProps

| Prop | Type | Description |
|------|------|-------------|
| `locale` | `string` | Active locale code (default: `"en"`) |
| `translations` | `Partial<Translations>` | Override keys for the current language |
| `customLanguages` | `Record<string, Partial<Translations>>` | Register new languages |
| `children` | `React.ReactNode` | Child components |

### I18nContextValue (from useI18n)

| Field | Type | Description |
|-------|------|-------------|
| `t` | `(key: TranslationKey) => string` | Typesafe translation function |
| `locale` | `string` | Current locale code |
| `changeLocale` | `(locale: string) => void` | Switch locale at runtime |
| `isRTL` | `boolean` | Whether the current locale is RTL |
| `direction` | `"ltr" \| "rtl"` | Convenience value for the `dir` attribute |

## Lazy Loading Behavior

Locale bundles use dynamic `import()` and are not included in the main bundle. On initialization, only English (fallback) and the requested locale are loaded. When `changeLocale` is called or the `locale` prop changes, the new bundle is fetched on demand. Already-loaded bundles are cached by i18next and not re-fetched.
